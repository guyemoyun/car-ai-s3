## 🔧 技术方案

### 架构设计

```
应用层 (Application)
    ├─ LVGL UI层
    ├─ 音频播报层
    └─ 语音交互层
         ↓
业务层 (Business Logic)
    └─ CarMonitor 协调器 ★核心
         ├─ 状态机
         ├─ 告警管理
         └─ 命令处理
         ↓
驱动层 (Drivers)
    ├─ 摄像头 + 人员检测
    ├─ 虚拟传感器 (当前)
    ├─ 真实传感器 (后续)
    ├─ IMU (可选)
    └─ 通信 (MQTT/WebSocket)
```

### 数据流

```
用户交互 (按键/触摸)
    ↓
应用程序 → Command Queue
    ↓
CarMonitor (100ms周期任务)
    ├─ 读取传感器
    ├─ 评估告警
    └─ 更新状态快照
    ↓
应用程序 ← GetSnapshot()
    ↓
LVGL更新 + 音频播报
```

### 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 传感器缺失 | 使用虚拟数据 | 快速验证逻辑，可切换到真实 |
| 告警存储 | RAM缓存 | 演示版本无需TF卡 |
| IMU集成 | 暂缓 | 优先级低，按键可替代 |
| 任务周期 | 100ms | 足够支持实时告警 |
| 命令队列 | 同步 + 异步混合 | GetSnapshot同步，SubmitCommand异步 |

## ⚠️ 已知限制与风险

### 当前限制

1. **虚拟数据**：非真实传感器，仅用于演示
2. **单一告警**：仅人员遗留告警完整，其他告警待实现
3. **无持久化**：无TF卡备份
4. **IMU缺失**：运动检测尚未实现
5. **界面缺失**：LVGL车载页面待实现

### 潜在风险

| 风险 | 影响 | 缓解方案 |
|------|------|----------|
| 摄像头/人员检测故障 | 无法检测人员 | 人员状态变UNKNOWN，不触发告警 |
| I²C总线故障 | 传感器读取失败 | 标记数据invalid，显示故障标志 |
| 任务栈溢出 | 系统崩溃 | 监控任务栈余量，预分配充足栈 |
| 内存泄漏 | 系统崩溃 | 定期检查内存，避免动态分配 |
