# M4（第一阶段）：人员检测 → 遗留告警链路

## 一、Context（为什么做这个）

车载项目已有：数据页 / 摄像头页、摄像头页 **QVGA 320×240 实时预览（10 FPS）**、`car_monitor` 的人员状态与停车遗留告警规则。

**缺口**：`person_data` 目前来自 `car_monitor` 内部的**虚拟传感器演示数据**，不是真实检测。`CarMonitorHelper::OnPersonDetectionResult()` 这个上报钩子**已存在但无人调用**。

**本阶段目标**：接入官方 `espressif/pedestrian_detect 0.3.2`（PICO_S8_V1）+ `esp-dl 3.3.13`，用**真实摄像头帧**做推理，把结果喂进已存在的钩子 → 复用已有告警规则，让"有人遗留"从演示变成真实。

**本阶段不含**：预览画面上的检测框标注（下一阶段单独做）。

## 二、已核实的关键事实

| 事实 | 证据 |
| --- | --- |
| **生效分区表是 `partitions/v1/16m.csv`**，根目录 `partitions.csv` 不参与构建 | `sdkconfig:593-594` `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions/v1/16m.csv"` |
| 分区现状：`ota_1` 结束于 `0x700000+6M = 0xD00000`，其后再到 16MB 还剩 **3 MiB** | `partitions/v1/16m.csv` |
| 模型文件 ≈ **425 KiB**（`pedestrian_detect_pico_s8_v1.espdl` = 435,328 B，S3 版） | 官方组件仓库 |
| 模型由**组件自带**并在 flash 时自动写入分区 | 组件 CMake：`esptool_py_flash_to_partition(flash "pedestrian_det" ...)`，仅需 Kconfig 选 `FLASH_PARTITION` + 分区表有同名分区 |
| `main/idf_component.yml` **没有** esp-dl / pedestrian_detect | 已读该文件 |
| 摄像头：QVGA 320×240 **RGB565**、`fb_count=2`、PSRAM；`Esp32Camera` 是唯一 `esp_camera_fb_get/return` 所有者，`fb_mutex_` 串行化 | `grw_esp32s3_board.cc`、`esp32_camera.h/.cc` |
| 现有 `GetPreviewFrame()` 是"拷帧 + RGB565 字节序转小端"，供 LVGL | `main/boards/common/esp32_camera.cc:145-186` |
| 上报钩子 `OnPersonDetectionResult(int,float)` **无调用者** | `main/car_monitor_helper.h:51`、`.cc:156`；全仓 grep 仅命中定义与文档 |
| `PERSON_DETECTION_VALIDITY_MS = 2000` → **检测周期必须 < 2 s** | `car_monitor.cc` → 否则 `person_data` 失效、`CheckPersonLeftAlert()` 直接 return false |
| 遗留告警规则链已就位：停车宽限 15 s + 连续 3 次有人 | `car_monitor.cc:415-450`、`PERSON_DETECTION_THRESHOLD` |
| 内部 RAM 极紧：稳态 ≈28 KB、最低 9~17 KB | 实测日志 `free sram: 27931 minimal sram: 11683` |
| **esp-dl 默认张量池全在 PSRAM**（`max_internal_size = 0`） | esp-dl 源码 `dl_memory_manager_greedy.cpp` / `dl_model_context.cpp` |

**结论**：内部 RAM 增量 ≈ 仅"识别任务栈"；PSRAM 增量 ≈ 模型 0.7~1.1 MiB + 识别帧缓冲 0.15 MiB。

## 三、实施步骤（分两段，可分别构建验收）

### 阶段 A：接入组件 + 验证兼容性（**先不动业务代码**）

1. `main/idf_component.yml` 追加：
   ```yaml
   espressif/pedestrian_detect:
     version: ~0.3.2
     rules:
     - if: target in [esp32s3]
   ```
2. `partitions/v1/16m.csv` 追加（根 `partitions.csv` 同步同样一行，仅保持一致）：
   ```
   pedestrian_det, data, spiffs, 0xD00000, 1M,
   ```
3. `sdkconfig.defaults.esp32s3` 追加：
   ```
   CONFIG_PEDESTRIAN_DETECT_MODEL_IN_FLASH_PARTITION=y
   CONFIG_FLASH_PEDESTRIAN_DETECT_PICO_S8_V1=y
   CONFIG_PEDESTRIAN_DETECT_PICO_S8_V1=y
   ```
4. **构建关卡**：`idf.py reconfigure` → `idf.py build` → `idf.py partition-table`。
   - 重点排查两类链接问题：`dl_fft` 被求解器从 0.3.1 升到 ≥0.8.0 后与 **esp-sr 2.1.5 预编译库**是否兼容；`esp_new_jpeg`(esp-dl 依赖) 与 `esp_jpeg 1.3.1`(esp32-camera 依赖) 是否符号/头冲突。
   - **这是本阶段头号风险**。若 build 失败或实机 AFE/wakenet 异常 → 退路：调 esp-dl 版本或暂缓 M4（需你决策）。

### 阶段 B：取帧出口（原样拷贝，不转字节序）

- `main/boards/common/camera.h`：加虚接口
  ```cpp
  virtual bool GetRawFrame(uint8_t* dst, size_t dst_size, int* out_w, int* out_h) {
      (void)dst; (void)dst_size; (void)out_w; (void)out_h; return false;
  }
  ```
- `main/boards/common/esp32_camera.h/.cc`：实现 `GetRawFrame()`——**与 `GetPreviewFrame()` 同构**（同一把 `fb_mutex_`、`fb_` 非空则只读借用、自己抓的用完立即归还），**唯一区别：原样 `memcpy`，不做 bswap**（模型要 `RGB565BE`）。

### 阶段 C：识别任务

新增 `main/car_person_detect.h` / `.cc`（单一职责）：

- 唯一持有 `PedestrianDetect` + 320×240 识别帧缓冲（PSRAM 153,600 B）；对外 `Start(interval_ms=500, chat_interval_ms=1000)` / `Stop()` / `IsRunning()`。
- 任务：`xTaskCreatePinnedToCore(..., 4096, ..., 1 /*优先级*/, 0 /*CPU0*/)`；启动后打印 `uxTaskGetStackHighWaterMark`。
- 循环：
  ```cpp
  dl::image::img_t img = {.data = s_buf, .width = 320, .height = 240,
                          .pix_type = dl::image::DL_IMAGE_PIX_TYPE_RGB565BE};
  auto &res = s_det->run(img);            // 返回内部列表引用，勿跨帧持有
  // 取最高 score 与命中数 → CarMonitorHelper::OnPersonDetectionResult(cnt>0?1:0, best);
  ```
- 阈值：`set_score_thr(0.7f, 0)`、`set_nms_thr(0.5f, 0)`（先按官方默认，误报高再往上调）。
- 频率：默认 **500 ms（2 Hz）**；`Application::GetInstance()->GetDeviceState()` 非 Idle/Unknown（小智会话中）→ 降到 **1000 ms**。**必须 < 2000 ms**。
- 降级（关键：不要产生"假无人"）：
  - 分区缺失/过小 → 记 `FAULT_NO_MODEL`，**不上报**；
  - 先判 `s_det->get_raw_model(0) != nullptr` 再 `run()`；
  - 取帧失败/推理失败 → **不上报**、`continue`（避免把"连续有人计数"清零）；
  - 连续失败约 30 s 后退避重建 detector，仍失败转 `FAULT_PERSISTENT` 并停止重建。
- 禁止开 esp-dl 多核调度（否则 Conv2D 会去抢 CPU1，威胁 AFE/wakenet）。

接线：
- `main/CMakeLists.txt`：`SOURCES` 加 `car_person_detect.cc`；`REQUIRES` 加 `pedestrian_detect`。
- `main/application.cc`（预览任务启动成功之后）：`CarPersonDetect::Start(500, 1000)`；失败只打警告、不阻塞启动。

## 五、验证（端到端）

**A. 构建与烧录**
1. `idf.py reconfigure`：观察 `dl_fft` 被升级（记下版本）。
2. `idf.py build`：**0 error**，无 duplicate symbol / undefined reference。
3. `idf.py partition-table`：确认 `pedestrian_det` @ `0xD00000`。
4. `idf.py -p COMx flash monitor`：出现 `Move and Pack models...`；启动日志见识别任务启动成功。

**B. 日志指标（每次迭代必看）**
- 识别启动时打印 internal / PSRAM 的 free（前后对比）；开发期可调 `get_raw_model(0)->profile_memory()` 实测张量占用。
- 每帧节流打印 `cnt=… best=… infer=…ms`。
- `CarUIHelper: Preview stats: fps=…` **必须仍 ≥5 FPS**。
- `SystemInfo: free sram` 最低值**不因识别进一步恶化**（内部 RAM 新增 ≤4 KB）。
- 无 `task_wdt`。

**C. 实物功能**
1. 切摄像头页 → 预览正常（≥5 FPS）。
2. 切到停车（GPIO11 短按）→ 真人站镜头前 → **约 16.5 s 内**出现 `car_monitor: ALERT: Person left!` 且 UI 出告警。
3. 无人静置 5 分钟 → **0 次告警**。
4. 语音并发（发起一次小智会话）→ 预览仍 ≥5 FPS、识别降到 1 Hz、无 WDT。

**D. 通道序确认（必须做一次）**
用有明显红/蓝色块的图片对准镜头：若检测异常或偏色 → 把 `DL_IMAGE_PIX_TYPE_RGB565BE` 改为 `BGR565BE`。

**E. 降级演练**
`esptool.py erase_region 0xD00000 0x100000` 后启动 → 应打"分区为空/模型加载失败"日志、**不崩**、预览与音频正常、**无假告警**；随后 `idf.py -p COMx flash` 恢复。
